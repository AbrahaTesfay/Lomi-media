# Deployment guide — staged launch

## Choose a deployment layout

**Recommended first production layout:** frontend on a managed static hosting/CDN provider; API on a managed Node.js service with a private persistent volume. Use a managed database such as PostgreSQL before heavy use. Do not deploy a SQLite file to a host with ephemeral storage: you may lose inquiries after redeploys or restarts.

## 1. Before deployment

1. Verify company ownership, approved logo, content, legal business name and contacts.
2. Replace all **concept portfolio cards** with authorized client work or keep them explicitly labeled.
3. Have the privacy policy reviewed and add a real privacy contact and data retention policy.
4. Decide on a domain; verify trademark and domain availability separately.
5. Run `npm install`, `npm run check` and `npm run build` locally.
6. Create a private Git repository, commit source and lockfile (generated by `npm install`), but never secret `.env` files or SQLite files.
7. Enable HTTPS, error monitoring, a backup plan and private admin access.

## 2. Frontend hosting

The frontend is under `client/`. With a monorepo-aware service, use repository root, installation `npm install`, build `npm run build`, publish directory `client/dist`. Alternatively set the service base folder to `client/` and use its own install/build commands, ensuring workspace dependency handling works.

For direct navigation to `/services`, `/contact` etc., configure SPA fallback to `index.html` on the static host. Netlify can use a `_redirects` file (`/* /index.html 200`); Vercel can use a rewrite rule. For stronger SEO, move marketing pages to pre-rendered HTML or SSR.

Set **build environment variable**:

```text
VITE_API_BASE_URL=https://api.YOUR-REAL-DOMAIN.example
```

Replace the example value with your actual deployed API HTTPS address. The example is NOT a real Lomi URL.

## 3. Backend hosting

Deploy the Node server from `server/` with `npm install` and `npm run start` (or root `npm run start:api`).

Environment variables:

```text
NODE_ENV=production
PORT=<your hosting provider's assigned port>
CORS_ORIGINS=https://YOUR-REAL-DOMAIN.example,https://www.YOUR-REAL-DOMAIN.example
DATABASE_PATH=/mount/secure/lomi-contacts.sqlite
TRUST_PROXY=false
```

Use only origins you own. Adjust `TRUST_PROXY` only when you understand the provider's trusted proxy setup. For a reverse proxy in front of the API, configure SSL termination, HTTP redirects and health checking.

**SQLite caveat:** SQLite is a single-file starter database. Managed hosting often has a temporary filesystem. Use a persistent volume with appropriate backups, or migrate to PostgreSQL before handling real customer inquiries. Your site can be publicly visible before enabling inquiries, but do not claim submitted data will be delivered if the backend is unavailable.

## 4. Email notifications and operations

This starter **saves** inquiries; it does not send email. Before a public launch, integrate a reputable transactional email service, verify your sending domain (SPF/DKIM/DMARC), protect API keys in server-only secrets, use retries and do not put secret credentials in React.

Avoid publicly accessible admin routes until you have a proper authentication/authorization plan. Use MFA and audit trails for future staff accounts. Set retention, deletion, exports and breach-response procedures.

## 5. Domain and international SEO

Connect the confirmed domain via host DNS records, enable automatic TLS certificates and verify it in Google Search Console. Create a route-aware XML sitemap, canonical URLs and page metadata. Add translations and `hreflang` only for actual translated pages. A basic SPA can render content with JavaScript, but pre-rendering or SSR will improve initial content delivery and make social previews more predictable.

## 6. Release acceptance checklist

- [ ] Home, Services, Work, About and Contact work at direct URLs
- [ ] All menus, buttons, keyboard paths, focus states and screen-reader labels checked
- [ ] Test at 375px, 768px and desktop widths
- [ ] Validate real inquiry submission, database persistence and staff receipt process
- [ ] Test rate limiting and spam filtering; ensure backups and access rules
- [ ] Check no placeholder case studies appear as actual clients
- [ ] Finalize privacy notice, company address, contacts and social accounts
- [ ] Test Core Web Vitals and production HTTP headers
- [ ] Check page titles/descriptions, sitemap, correct indexing and social cards
- [ ] Monitor logs and test restore/rollback before announcing the site
